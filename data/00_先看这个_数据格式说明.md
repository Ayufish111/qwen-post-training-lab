# 第一个训练样本

下面是一条最普通的 SFT 训练数据。暂时不要看工具调用，也不要看 DPO。

```json
{
  "messages": [
    {
      "role": "user",
      "content": "LoRA 是什么？"
    },
    {
      "role": "assistant",
      "content": "LoRA 是一种参数高效微调方法。它冻结原模型参数，只训练额外加入的低秩矩阵。"
    }
  ]
}
```

它只表达一件事：

```text
用户问：LoRA 是什么？
模型应该回答：LoRA 是一种参数高效微调方法……
```

`messages` 是一段对话；`role` 表示这句话是谁说的；`content` 是具体文本。

## 为什么真实文件只有一行

训练文件使用 `.jsonl` 格式：一行就是一条上面这样的训练样本。

```jsonl
{"messages":[{"role":"user","content":"LoRA 是什么？"},{"role":"assistant","content":"LoRA 是一种参数高效微调方法。"}]}
{"messages":[{"role":"user","content":"QLoRA 和 LoRA 有什么区别？"},{"role":"assistant","content":"QLoRA 会先把基础模型量化到低比特，再训练 LoRA 适配器。"}]}
```

因此 VS Code 左侧看到两行，代表文件里目前放了两条训练样本，不是“只有两句话”。项目刚建立时只放少量样例用于验证格式；之后真实训练集会有数千到数万行。

## DPO 文件为什么更复杂

`data/dpo/sample.jsonl` 是后续的偏好数据。它额外保存：

```text
prompt   同一个问题
chosen   更好的回答
rejected 较差的回答
```

当前不需要读它。先理解 SFT 的“问题 -> 标准回答”，再学习 DPO。
